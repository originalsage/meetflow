# 后端接口快速测试指南

## 一、准备工作

### 1. 确保数据库已初始化
执行之前提供的建表SQL，确保：
- 数据库 `meetflow` 已创建
- 表 `user`、`meeting_room`、`reservation` 已创建
- 测试数据已插入（至少要有管理员账号）

### 2. 启动后端服务
运行 `MeetflowApplication.java`，确保服务运行在 `http://localhost:8080`

### 3. 在 Apifox 中导入接口文档
- 打开 Apifox
- 导入 `api-docs-openapi.yaml` 文件

## 二、快速测试步骤

### 步骤1：登录获取 Token

**接口**: `POST /api/auth/login`

**请求体**（管理员）:
```json
{
  "username": "admin",
  "password": "admin123",
  "role": 1
}
```

**响应示例**:
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "userInfo": {
      "id": 1,
      "username": "admin",
      "name": "系统管理员",
      "role": 1
    }
  }
}
```

**操作**:
1. 复制返回的 `token` 值
2. 在 Apifox 环境变量中设置 `token` 变量
3. 在需要认证的接口中，Header 添加：`Authorization: Bearer {{token}}`

### 步骤2：测试会议室接口（无需登录）

**2.1 获取所有会议室**
- `GET /api/meeting-rooms`
- 应该返回会议室列表

**2.2 获取会议室详情**
- `GET /api/meeting-rooms/1`
- 返回ID为1的会议室详情

**2.3 筛选可用会议室**
- `GET /api/meeting-rooms/available?date=2024-01-15&startTime=9&endTime=11&attendeeCount=20`
- 返回符合条件的可用会议室

### 步骤3：测试预约接口（需要登录）

**3.1 创建预约**
- `POST /api/reservations`
- Header: `Authorization: Bearer {{token}}`
- 请求体:
```json
{
  "meetingRoomId": 1,
  "meetingTitle": "项目讨论会",
  "reservationDate": "2024-01-15",
  "startTime": 9,
  "endTime": 11,
  "attendeeCount": 15
}
```

**3.2 查询我的预约**
- `GET /api/reservations/my`
- Header: `Authorization: Bearer {{token}}`
- 可选参数: `?status=0` (0-待审批，1-已通过，2-已驳回，3-已取消，4-已完成)

**3.3 获取预约详情**
- `GET /api/reservations/1`
- 返回ID为1的预约详情

**3.4 取消预约**
- `PUT /api/reservations/1/cancel`
- Header: `Authorization: Bearer {{token}}`

### 步骤4：测试管理员接口（需要管理员Token）

**4.1 添加会议室**
- `POST /api/meeting-rooms`
- Header: `Authorization: Bearer {{token}}`
- 请求体:
```json
{
  "name": "测试会议室",
  "roomNumber": "T001",
  "capacity": 30,
  "area": 60.00,
  "purpose": "测试用途",
  "status": 1
}
```

**4.2 上传会议室照片**
- `POST /api/meeting-rooms/upload`
- Header: `Authorization: Bearer {{token}}`
- Content-Type: `multipart/form-data`
- Body: 选择文件上传

**4.3 设置会议室状态**
- `PUT /api/meeting-rooms/1/status?status=0`
- Header: `Authorization: Bearer {{token}}`
- status: 0-不可预约，1-可预约

**4.4 查询所有预约**
- `GET /api/reservations/all`
- Header: `Authorization: Bearer {{token}}`
- 可选参数: `?status=0`

**4.5 审批预约（通过）**
- `PUT /api/reservations/1/approve`
- Header: `Authorization: Bearer {{token}}`
- 请求体: `{}` (空对象表示通过)

**4.6 审批预约（驳回）**
- `PUT /api/reservations/1/approve`
- Header: `Authorization: Bearer {{token}}`
- 请求体:
```json
{
  "rejectReason": "该时间段已被占用"
}
```

**4.7 获取一周预约情况**
- `GET /api/reservations/weekly?weekStartDate=2024-01-15`
- Header: `Authorization: Bearer {{token}}`

**4.8 获取当天各时段占用情况**
- `GET /api/reservations/daily?date=2024-01-15`
- Header: `Authorization: Bearer {{token}}`

## 三、常见错误处理

### 1. 401 未授权
- 原因：Token 过期或未设置
- 解决：重新登录获取新 Token

### 2. 403 无权限
- 原因：普通用户访问管理员接口
- 解决：使用管理员账号登录

### 3. 时间冲突错误
- 原因：该时间段已被预约
- 解决：选择其他时间段或会议室

### 4. 容量不足错误
- 原因：参会人数超过会议室容量
- 解决：选择容量更大的会议室

### 5. 密码错误
- 原因：数据库中的密码是明文，需要BCrypt加密
- 解决：使用BCrypt加密后的密码，或修改登录逻辑支持明文密码（仅测试环境）
